# RA8P1 V13 固件对接手册

日期：2026-07-29  
适用平台：RA8P1，CPU0 Cortex-M85 + Ethos-U55，CPU1 Cortex-M33  
包版本：`RA8P1_RF_V13_ACTIVITY_20260729`

## 1. 先看结论

当前应上板集成 **V13**。V13 的检测层是已经通过 INT8、Vela 和 ABI 门禁的 V12 双模型，状态层是在 CPU1 上运行的 Q20.12 Leaky SPRT。它不改变模型输入、模型输出顺序、量化参数、arena offset 或 V12 检测框协议。

| 方案 | 已验证结果 | 是否符合当前稀疏四频点采集 | 裁决 |
|---|---|---|---|
| V11 | 图传 grouped validation：P/R/F2=`0.9757/0.9870/0.9848` | 否；需要第三模型、同频 100 ms 上下文和跨周期处理 | 离线图传效果最好，但不能直接作为当前固件方案 |
| V12 | 五类 non-overlap：P/R/F2=`0.8827/0.6059/0.6455`；one-tile：`0.9041/0.6613/0.6971` | 是；V2+V3、`CPU operators=0`、arena=`189312 B` | 可部署的事件检测基线，但没有正式状态融合实现 |
| **V13** | 检测指标与 V12 相同；增加 C/Python `12/12` Golden 一致的四频点状态融合 | **是** | **当前综合性能和可部署性最优** |

V13 的优势是系统级结果更可靠，不是声称单窗 CNN 精度高于 V12。代理真空窗回放的错误进入 WORKING 约为 `2.79 次/小时`；它不是真实连续 IQ 的最终指标，实板长时门禁仍需完成。

## 2. 包内文件如何使用

将下列文件加入固件工程：

| 包内路径 | 目标 | 用法 |
|---|---|---|
| `firmware/include/rf_v12_sparse_contract.h` | CPU0/CPU1 公共 include | V12 tile、类别、框和硬件常量 |
| `firmware/include/rf_v12_model_data.h` | CPU0 include | V2/V3 Vela command/weight 声明 |
| `firmware/src/rf_v12_v2_model.c` | CPU0 编译单元 | V2 command/weight 数据 |
| `firmware/src/rf_v12_v3_model.c` | CPU0 编译单元 | V3 command/weight 数据 |
| `firmware/include/rf_v13_activity_fusion.h` | CPU0/CPU1 公共 include | V13 消息、状态、API 和 ABI 静态断言 |
| `firmware/include/rf_v13_activity_calibration.h` | CPU1 include | 正式标定配置声明 |
| `firmware/src/rf_v13_activity_fusion.c` | CPU0/CPU1 可链接库 | 轮消息 helper 和状态融合实现 |
| `firmware/src/rf_v13_activity_calibration.c` | CPU1 编译单元 | 正式 LLR 表与 `5.0/0.5` 迟滞参数 |

推荐把 `rf_v13_activity_fusion.c` 编译为 CPU0、CPU1 都能链接的静态库；若工程不共享库，也可分别编译一份。模型 `.tflite` 和 `.npz` 用于审计与 Golden，不需要随固件运行时一起烧录；CPU0 使用包内生成的 Vela command/weight C 数组。

禁止使用 `g_rf_v13_smoke_config` 作为正式配置。生产调用必须传入：

```c
&g_rf_v13_deployment_config
```

smoke 配置仍保留用户最初给定的 `4.0/1.0` 阈值；正式标定配置是 `WORKING enter=5.0`、`WORKING exit<0.5`。

## 3. 保持 V12 检测 ABI 不变

模型输入固定为 `[1,204,115,4] NHWC INT8`，共 `93840 B`，输入 arena offset 为 `94656`。V2 和 V3 顺序复用 `189312 B` arena：

```c
memcpy(arena + RF_V12_ARENA_INPUT_OFFSET, feature_staging,
       RF_V12_FEATURE_BYTES);
run_v2();
copy_v2_physical_outputs_0_2_3_4_to_dtcm(); /* physical 1 必须忽略 */

memcpy(arena + RF_V12_ARENA_INPUT_OFFSET, feature_staging,
       RF_V12_FEATURE_BYTES);
run_v3();
copy_v3_output_to_dtcm();

decode_local_max_components_fixed_boxes_and_global_top4();
```

必须先按各 head 的 `scale/zero_point` 反量化成 logit，再转概率并执行全类别 top-4；不同 head 的 INT8 数字不能直接比较。框继续走原 `rf_v12_tile_payload_t`，V13 状态消息不携带框坐标，也不能跨 retune 或跨频点合成新框。

## 4. 512 B IPC 类型区分

V12 tile 和 V13 round 都恰好为 `512 B`。若共用同一个四槽结果 ring，CPU1 先读首个 `uint32_t magic`：

| 消息 | magic | 小端内存字符 |
|---|---:|---|
| V12 tile | `0x53323156` | `V12S` |
| V13 round | `0x46333156` | `V13F` |

```c
typedef union rf_ipc_decode_slot {
    rf_v12_tile_payload_t v12;
    rf_v13_cpu0_round_message_t v13;
    uint8_t bytes[512];
} rf_ipc_decode_slot_t;

static void consume_shared_slot(const volatile uint8_t *shared_slot)
{
    rf_ipc_decode_slot_t local; /* union 保证 uint64_t 所需自然对齐 */
    uint32_t magic;

    ipc_invalidate_and_acquire(shared_slot, sizeof(local));
    memcpy(local.bytes, (const void *)shared_slot, sizeof(local));
    ipc_acknowledge_slot(); /* 此后生产者才可复用共享 slot */
    memcpy(&magic, local.bytes, sizeof(magic));

    if (magic == RF_V12_ABI_MAGIC) {
        consume_v12_tile(&local.v12);
    } else if (magic == RF_V13_ACTIVITY_MAGIC) {
        consume_v13_round(&local.v13);
    } else {
        count_bad_ipc_message();
    }
}
```

不要把任意 `uint8_t *` 直接 cast 成含 `uint64_t` 的消息结构。先复制到自然对齐的本地 union，既避免未对齐访问，也避免 CPU0 复用共享 slot 时 CPU1 读到撕裂消息。

如果 V12 tile 与 V13 round 混用原结果 ring，每轮消息量会从 4 条增加到 5 条。优先给 V13 分配独立的 `512 B` activity mailbox；若必须共用四槽 ring，必须实测 producer/consumer ack、峰值积压和 10000 窗稳定性，不能只因单条结构仍为 512 B 就认定容量足够。

两个核均为小端时可使用上述共享结构。不要添加 `#pragma pack`，头文件中的 offset/size 静态断言依赖自然对齐。发布 slot 前 CPU0 必须 clean cache 并执行 release barrier；CPU1 消费前 invalidate cache 并执行 acquire barrier。slot 必须在 CPU1 确认消费后才能复用。

V12 与 V13 的逻辑类 ID 当前恰好一致，但 V2 physical output index 和 DTCM slot 顺序并不一致。编译时锁定逻辑类映射，禁止把 physical index 直接当成 class ID：

```c
_Static_assert(RF_V12_CLASS_DJI_CONTROL == RF_V13_CLASS_DJI_CONTROL, "class ABI");
_Static_assert(RF_V12_CLASS_DJI_VIDEO == RF_V13_CLASS_DJI_VIDEO, "class ABI");
_Static_assert(RF_V12_CLASS_AT9S == RF_V13_CLASS_AT9S, "class ABI");
_Static_assert(RF_V12_CLASS_T12 == RF_V13_CLASS_T12, "class ABI");
_Static_assert(RF_V12_CLASS_XIAOBAWANG == RF_V13_CLASS_XIAOBAWANG, "class ABI");
```

## 5. CPU0：构造完整四频点轮消息

### 5.1 轮次约束

中心槽固定为：

```text
0 = 2420 MHz
1 = 2464 MHz
2 = 5760 MHz
3 = 5816 MHz
```

每个 V12 tile 仍立即发送，供 CPU1 显示检测框。CPU0 另外按 `round_index` 累积四个 tile，在轮关闭时再发送一个 V13 round。单轮最多 `4 tile x 4 event = 16` 条 evidence。

一个轮次只有同时满足以下条件才可作为负证据：

- `observed_slot_mask == valid_slot_mask == 0x0f`；
- `RF_V13_ROUND_COMPLETE` 与 `RF_V13_ROUND_V12_TILES_VALIDATED` 都置位；
- 无 CRC、缺包、ring overflow、retune unlocked、capture timeout、背景未就绪、序号异常或结果截断；
- 四个 tile 都是当前背景代际下的 `RF_V12_TILE_VALID`。

任何一项失败都要发送无效轮，而不是丢掉消息。CPU1 对无效轮严格保持 E，不泄漏、不减 `0.25`。

### 5.2 初始化与添加事件

以下代码展示接入顺序；`round_builder_t` 是固件自己的临时聚合对象，不属于 ABI：

```c
typedef struct {
    rf_v13_cpu0_round_message_t message;
    uint8_t started;
} round_builder_t;

static round_builder_t g_round;

static void round_begin(const rf_v12_tile_payload_t *tile,
                        uint32_t v13_message_sequence)
{
    rf_v13_cpu0_round_message_init(
        &g_round.message,
        v13_message_sequence,
        tile->round_index,
        tile->capture_start_time_us,
        tile->capture_end_time_us);
    g_round.started = 1u;
}
```

`round_begin()` 只能在 tile 结构校验通过后调用。至少检查 magic/ABI、中心槽与中心频率映射、采样率、样本数、时间顺序和 event 数量：

```c
static int v12_tile_structure_is_valid(const rf_v12_tile_payload_t *tile)
{
    static const uint64_t centers[RF_V12_CENTER_COUNT] = {
        RF_V12_CENTER_2420_HZ, RF_V12_CENTER_2464_HZ,
        RF_V12_CENTER_5760_HZ, RF_V12_CENTER_5816_HZ
    };

    if (tile == NULL || tile->magic != RF_V12_ABI_MAGIC ||
        tile->abi_version_major != RF_V12_ABI_VERSION_MAJOR ||
        tile->abi_version_minor != RF_V12_ABI_VERSION_MINOR ||
        tile->center_index >= RF_V12_CENTER_COUNT ||
        tile->event_count > RF_V12_MAX_BOXES_PER_TILE ||
        tile->sample_rate_hz != RF_V12_SAMPLE_RATE_HZ ||
        tile->tile_samples != RF_V12_TILE_SAMPLES ||
        tile->capture_start_time_us > tile->capture_end_time_us) {
        return 0;
    }
    return tile->capture_center_frequency_hz == centers[tile->center_index];
}

static int v12_events_are_well_formed(const rf_v12_tile_payload_t *tile)
{
    uint8_t i;
    for (i = 0u; i < tile->event_count; ++i) {
        const rf_v12_visible_event_t *event = &tile->events[i];
        if (event->class_id >= RF_V12_CLASS_COUNT ||
            event->confidence_q15 > RF_V12_CONFIDENCE_Q15_ONE ||
            event->visible_start_sample >= event->visible_end_sample ||
            event->visible_end_sample > tile->tile_samples ||
            event->frequency_low_offset_hz >=
                event->frequency_high_offset_hz) {
            return 0;
        }
    }
    return 1;
}
```

非法 `class_id` 不能交给 `rf_v13_cpu0_add_v12_detection()` 判断，因为 helper 对“类别非法”和“类别不允许出现在该频段”都返回 `0`。前者必须把整轮标为 `RF_V13_INVALID_MALFORMED_EVIDENCE`，后者才是正常频段门控。

接收每个 tile 时，必须先完成结构、轮次、序号和重复槽校验。只有完整有效的 tile 才能添加 evidence；无效 tile 只设置轮次无效原因。更新轮结束时间后再添加 detection，否则 detection timestamp 可能超出消息时间区间：

```c
static void round_add_tile(const rf_v12_tile_payload_t *tile)
{
    uint8_t i;
    uint8_t slot_bit;

    if (!v12_tile_structure_is_valid(tile)) {
        g_round.message.invalid_reason_flags |=
            RF_V13_INVALID_V12_ABI | RF_V13_INVALID_MALFORMED_EVIDENCE;
        return;
    }
    if (tile->round_index != g_round.message.round_index) {
        g_round.message.invalid_reason_flags |= RF_V13_INVALID_TILE_SEQUENCE;
        return;
    }

    slot_bit = (uint8_t)(1u << tile->center_index); /* center_index 已校验 */
    if ((g_round.message.observed_slot_mask & slot_bit) != 0u ||
        (g_round.message.observed_slot_mask != 0u &&
         tile->sequence != g_round.message.last_v12_tile_sequence + 1u)) {
        g_round.message.invalid_reason_flags |= RF_V13_INVALID_TILE_SEQUENCE;
        return;
    }

    if (g_round.message.observed_slot_mask != 0u &&
        tile->capture_start_time_us < g_round.message.round_end_time_us) {
        g_round.message.invalid_reason_flags |= RF_V13_INVALID_TIMESTAMP;
        return; /* 四次分时采集不得倒退或重叠 */
    }
    if (tile->capture_start_time_us < g_round.message.round_start_time_us) {
        g_round.message.round_start_time_us = tile->capture_start_time_us;
    }
    if (tile->capture_end_time_us > g_round.message.round_end_time_us) {
        g_round.message.round_end_time_us = tile->capture_end_time_us;
    }
    if (g_round.message.observed_slot_mask == 0u) {
        g_round.message.first_v12_tile_sequence = tile->sequence;
    }
    g_round.message.last_v12_tile_sequence = tile->sequence;
    g_round.message.observed_slot_mask |= slot_bit;

    if (tile->tile_validity != RF_V12_TILE_VALID || tile->flags != 0u) {
        map_v12_tile_failure_to_v13_invalid_flags(tile, &g_round.message);
        return; /* 无效 tile 绝不贡献正证据 */
    }
    if (!v12_events_are_well_formed(tile)) {
        g_round.message.invalid_reason_flags |=
            RF_V13_INVALID_MALFORMED_EVIDENCE;
        return;
    }

    g_round.message.valid_slot_mask |= slot_bit;

    for (i = 0u; i < tile->event_count; ++i) {
        const rf_v12_visible_event_t *event = &tile->events[i];
        const uint64_t event_time_us = event_midpoint_time_us(tile, event);
        const uint8_t roi = roi_verdict_for_event(tile, event);
        const int16_t period_bonus_q12 = period_soft_bonus_for_event(tile, event);

        const int added = rf_v13_cpu0_add_v12_detection(
                &g_round.message,
                event->class_id,
                tile->center_index,
                event->confidence_q15,
                roi,
                period_bonus_q12,
                event->flags,
                event_time_us);
        if (added < 0) {
            if ((g_round.message.round_flags &
                 RF_V13_ROUND_EVIDENCE_TRUNCATED) != 0u) {
                g_round.message.invalid_reason_flags |=
                    RF_V13_INVALID_RESULT_TRUNCATED;
            } else {
                g_round.message.invalid_reason_flags |=
                    RF_V13_INVALID_MALFORMED_EVIDENCE;
            }
        }
    }
}
```

`event_midpoint_time_us()` 应按事件可见样本中点和 `60 MSPS` 计算，并夹紧到 capture 起止时间。周期奖励当前上限为 `1229 Q12 = 0.3`；没有经过验证的周期实现时必须传 `0`。

`map_v12_tile_failure_to_v13_invalid_flags()` 必须是确定映射，不能把采集错误遗漏为普通空窗：

```c
static void map_v12_tile_failure_to_v13_invalid_flags(
    const rf_v12_tile_payload_t *tile,
    rf_v13_cpu0_round_message_t *round)
{
    if (tile->tile_validity == RF_V12_TILE_BACKGROUND_NOT_READY ||
        (tile->flags & RF_V12_TILE_BACKGROUND_RESET) != 0u) {
        round->invalid_reason_flags |= RF_V13_INVALID_BACKGROUND_NOT_READY;
    }
    if (tile->tile_validity == RF_V12_TILE_INVALID ||
        (tile->flags & (RF_V12_TILE_ADC_SATURATION |
                        RF_V12_TILE_CAPTURE_TIMEOUT)) != 0u) {
        round->invalid_reason_flags |= RF_V13_INVALID_CAPTURE;
    }
    if ((tile->flags & RF_V12_TILE_CRC_ERROR) != 0u)
        round->invalid_reason_flags |= RF_V13_INVALID_CRC;
    if ((tile->flags & RF_V12_TILE_PACKET_GAP) != 0u)
        round->invalid_reason_flags |= RF_V13_INVALID_IQ_GAP;
    if ((tile->flags & RF_V12_TILE_RETUNE_UNLOCKED) != 0u)
        round->invalid_reason_flags |= RF_V13_INVALID_RETUNE_UNLOCKED;
    if ((tile->flags & RF_V12_TILE_RING_OVERFLOW) != 0u)
        round->invalid_reason_flags |= RF_V13_INVALID_RING_OVERFLOW;
    if ((tile->flags & RF_V12_TILE_RESULT_TRUNCATED) != 0u) {
        round->invalid_reason_flags |= RF_V13_INVALID_RESULT_TRUNCATED;
        round->round_flags |= RF_V13_ROUND_EVIDENCE_TRUNCATED;
    }
}
```

轮关闭时还要断言四条 tile 的 `last_v12_tile_sequence - first_v12_tile_sequence == 3`。不连续、重复、跨轮或乱序均设 `RF_V13_INVALID_TILE_SEQUENCE`，不得置 `RF_V13_ROUND_V12_TILES_VALIDATED`。

### 5.3 ROI 判定

ROI 值必须来自纹理复核，不应由 CNN 分数自行伪造：

- `RF_V13_ROI_PASS`：复核通过，证据乘 `1.0`；
- `RF_V13_ROI_UNKNOWN`：没有复核或结果不确定，证据乘 `0.5`；
- `RF_V13_ROI_FAIL`：不进入工作状态证据，但 V12 可见框仍照常显示。

如果生产固件尚未接入 ROI 纹理复核，统一发送 `RF_V13_ROI_UNKNOWN`。不要临时把所有事件标为 PASS。

### 5.4 关闭并发送轮次

```c
static void round_close_and_publish(void)
{
    rf_v13_cpu0_round_message_t *m = &g_round.message;

    if (m->observed_slot_mask == RF_V13_CENTER_SLOT_MASK &&
        m->last_v12_tile_sequence - m->first_v12_tile_sequence != 3u) {
        m->invalid_reason_flags |= RF_V13_INVALID_TILE_SEQUENCE;
    }

    if (m->observed_slot_mask == RF_V13_CENTER_SLOT_MASK) {
        m->round_flags |= RF_V13_ROUND_COMPLETE;
    } else {
        m->invalid_reason_flags |= RF_V13_INVALID_INCOMPLETE;
    }

    if (m->valid_slot_mask == RF_V13_CENTER_SLOT_MASK &&
        m->invalid_reason_flags == RF_V13_INVALID_NONE) {
        m->round_flags |= RF_V13_ROUND_V12_TILES_VALIDATED;
    }

    if (m->round_flags & RF_V13_ROUND_EVIDENCE_TRUNCATED) {
        m->invalid_reason_flags |= RF_V13_INVALID_RESULT_TRUNCATED;
    }

    ipc_publish_512_bytes(m); /* clean cache + release barrier */
    g_round.started = 0u;
}
```

AT9S、T12、小霸王在 5.8 GHz 会由 helper 返回 `0`，这是正常频段门控，不是消息错误。大疆遥控和大疆图传允许四个中心槽。大疆遥控跳频时不要求下一轮频率坐标相同。

## 6. CPU1：应用状态融合

### 6.1 初始化

```c
#include "rf_v13_activity_calibration.h"
#include "rf_v13_activity_fusion.h"

static rf_v13_activity_fusion_t g_activity;

void app_rf_activity_init(void)
{
    rf_v13_activity_fusion_init(&g_activity);
}
```

`message_sequence` 和 `round_index` 在 CPU0 正常运行期间必须单调递增。CPU0 重启后若从 0 重新计数，CPU1 会把新消息判断为 stale；因此启动协议必须携带 CPU0 boot epoch/reset 控制事件，并在 CPU1 确认新 epoch 时调用一次 `rf_v13_activity_fusion_init()`。另一种做法是把两个序号持久化为跨重启单调值。禁止仅等待数值自然追上旧序号。

`g_activity` 占 `304 B` RAM；正式标定表占 `212 B` Flash/只读区。状态层不使用 NPU，不增加 arena 和 heatmap DTCM。

### 6.2 消费轮消息

```c
static void consume_v13_round(const rf_v13_cpu0_round_message_t *message)
{
    rf_v13_apply_result_t result = rf_v13_activity_fusion_apply_round(
        &g_activity,
        message,
        &g_rf_v13_deployment_config);

    switch (result) {
    case RF_V13_APPLY_OK:
    case RF_V13_APPLY_HELD_INVALID_ROUND:
        publish_four_activity_objects_to_ui();
        break;
    case RF_V13_APPLY_IGNORED_DUPLICATE:
    case RF_V13_APPLY_IGNORED_STALE:
        break;
    case RF_V13_APPLY_BAD_ARGUMENT:
    case RF_V13_APPLY_BAD_MESSAGE:
    default:
        count_v13_protocol_error();
        break;
    }
}
```

读取四个对象：

```c
for (unsigned id = 0; id < RF_V13_OBJECT_COUNT; ++id) {
    const rf_v13_object_state_t *s = rf_v13_activity_fusion_get(
        &g_activity, (rf_v13_object_id_t)id);
    ui_update_activity(
        id,
        s->activity_state,
        s->energy_q12,                 /* 显示值可除以 4096.0 */
        s->last_positive_time_us,
        s->last_positive_source_class,
        s->last_positive_band_mask,
        s->last_positive_center_slot,
        s->last_round_complete,
        s->last_round_valid,
        s->last_reason_flags,
        s->last_transition_reason_flags,
        s->last_transition_time_us);
}
```

同类同轮多个框只取最大 LLR；DJI 对象取大疆遥控和图传中的最大证据，并保留胜出来源。框数量不会线性增加 E。`last_positive_*` 表示最近一次正证据，不一定来自当前轮；判断当前轮质量必须同时检查 `last_round_complete` 和 `last_round_valid`，不能只看前者。

### 6.3 UI 三态

| 状态值 | 推荐中文 | 含义 |
|---|---|---|
| `RF_V13_ACTIVITY_WORKING` | 检测到工作射频 | 证据达到进入阈值，进入后需降到 0.5 以下才退出 |
| `RF_V13_ACTIVITY_UNCERTAIN` | 射频状态不确定 | 有证据但不足以稳定确认，或正在迟滞退出 |
| `RF_V13_ACTIVITY_NO_RF_OBSERVED` | 未观察到目标射频 | 有效观察下未建立目标证据 |

绝对禁止把 `NO_RF_OBSERVED` 显示成“设备关闭”。只有外部明确的电源/控制状态才能显示 `OFF`。长时间没有有效完整轮时，E 会保持；UI 可另外显示“扫描数据陈旧/扫描异常”，但不能据此把状态改成 OFF 或注入负证据。

上电初始化或 CPU0 epoch 重置后，在 `g_activity.initialized == 0` 时显示“扫描初始化中”。即使收到过无效轮，只要四对象的 `last_round_valid == 0`，也应显示“扫描不可用/数据不完整”，不能直接展示“未观察到目标射频”。只有至少应用过一个完整有效轮后，`NO_RF_OBSERVED` 才能作为 RF 观察结果显示。freshness timeout 只控制额外的“数据陈旧”标志，不改变三态和 E。

## 7. 定点参数与状态时序

正式部署参数来自 `g_rf_v13_deployment_config`：

```text
E_new = clip(round_q12(0.85 * E_old) + LLR_round, -8, 8)
WORKING enter: E >= 5.0
WORKING exit:  E < 0.5
complete valid miss: -0.25
invalid/incomplete round: exact hold
```

| 参数 | Q20.12 |
|---|---:|
| 0.85 leak | 3482 |
| enter 5.0 | 20480 |
| exit 0.5 | 2048 |
| miss -0.25 | -1024 |
| clip [-8,8] | [-32768,32768] |
| period bonus cap 0.3 | 1229 |

实现内部用 `int64_t` 做乘法和中间加法，再回到 `int32_t Q20.12`，Cortex-M33 不需要浮点。当前约 `586 ms/round` 时，强证据通常两轮进入 WORKING；进入后约 6 至 8 个完整无检测轮才退出。无效轮不会缩短保持时间。

## 9. 联调顺序

1. 仅接 V12 双模型，确认输入量化、V2 输出复制时机、V3 输出和每 tile 最多四框。
2. 对真实 IQ 建立 `IQ -> 204x115x4 INT8` byte-exact Golden；这是当前包仍未提供的关键门禁。
3. CPU0 在日志中打印每轮 `round_index/message_sequence/observed_mask/valid_mask/invalid_flags/evidence_count`。
4. CPU1 比较包内 `golden/activity/c_q20_12_trace.csv`，确认 E、三态和原因位一致。
5. 注入 CRC 错误、缺包、ring overflow、背景未 ready 和漏频点，确认 E 逐 bit 不变。
6. 分别只播放大疆遥控、只播放大疆图传，二者都应建立 DJI WORKING；遥控跨 2.4/5.8 GHz 跳频不应丢状态。
7. 播放单次孤立高分假框，不得进入 WORKING；播放持续 Wi-Fi/蓝牙，统计每小时错误进入次数。
8. 实测 CPU1 周期、IPC p95、NPU 双模型 p50/p95、arena 覆盖和 10000 窗队列稳定性。

正式发布报告至少记录：固件 commit、V13 ZIP SHA-256、V2/V3 模型 SHA-256、实际 SDR gain、背景代际策略、Vela 版本/config、NPU 时钟、状态参数和长时回放时长。

## 10. 验收标准

检测框继续使用 V12 指标口径，同时增加状态级门禁：

- 单次孤立误报不得进入 WORKING；
- 大疆仅遥控或仅图传均可进入 WORKING；
- 短时漏检和跳频改变频率不应导致状态闪烁；
- 丢包和不完整轮不得使 E 下降；
- AT9S/T12/小霸王的 5.8 GHz 框不得进入状态证据；
- 真实空窗和 Wi-Fi/蓝牙长时回放必须报告每小时错误进入 WORKING 次数；
- `NO_RF_OBSERVED` 的 UI、日志和外部协议均不得解释为 OFF；
- 真实板端 arena 不超过 `198256 B`，NPU CPU fallback 必须为 0；
- 完成真实连续四频点 IQ、目标 SDR gain、IQ 特征 byte parity 和 Cortex-M33 p95 后，才能把状态从“固件集成候选”改为“实板验收通过”。

## 11. 回滚

V13 是 V12 上的独立状态层。发生问题时：

1. 停止 CPU0 发布 `V13F` round 消息；
2. 停止 CPU1 调用 `rf_v13_activity_fusion_apply_round()`，恢复 V12 原 UI 行为；
3. 保持 V2/V3 模型 blob、输入输出 ABI、V12 tile 和框解码不变；
4. 使用未修改的 `RA8P1_RF_V12_SPARSE_20260729.zip` 回滚。

回滚不需要修改在线标注服务或标注数据库，也不需要重新烧录一套不同的检测模型权重。
